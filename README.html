A — Getting Started
1
First-Time Setup
One-time

Open a terminal in the project folder and install dependencies:

Install dependencies
pip install -r requirements.txt

Copy key.env.example to key.env in the same folder, then fill in ANTHROPIC_API_KEY — this is the only credential the app needs.

ℹ
Edit the bank list Open config.py and update the BANKS list with the banks you claim from. This list only populates the dropdown in Step 2 — it does not need to match any folder path.
🔒
No external access, by design There is no SharePoint/Graph client, no URL fetching, and no credentials beyond the Anthropic API key anywhere in this app. Statements and receipts only ever enter via direct browser upload, and nothing is written back anywhere automatically.
2
Launching the App
Daily

Open a terminal in the project folder and run:

Start the app
streamlit run app.py

A browser tab opens automatically at the app's form.

⛔
Won't start: "ANTHROPIC_API_KEY not set" Add the key to key.env (Step 1), then restart the app.
B — Running a Reconciliation
3
Choose Bank, Upload Statement & Receipts
Per statement
  • Choose Bank from the dropdown — this is a label passed to Claude as a hint when reading the statement, and used to name the output. It doesn't need to match any folder path.
  • Upload the statement — a single credit card statement PDF.
  • Upload the receipts — select every receipt/invoice file for this statement at once (Ctrl/Cmd-click multiple files, or drag a whole selection in). Accepts PDF, PNG, and JPG.
📁
"Uploading a folder" in practice Browsers don't have a native folder-upload control. Selecting every file in a folder at once in the file picker achieves the same result — this is by design, not a limitation to work around.
ℹ
Scanned statements are handled automatically If the PDF has no extractable text (a scanned copy), the app automatically falls back to sending page images to Claude instead — no action needed from you.
4
Confirm Where You'll Extract the ZIP
⚠ Important

Before running, the app asks: "Where will you extract the downloaded ZIP?" — defaulting to your Downloads folder (auto-detected from your Windows account, not hardcoded).

⛔
This is baked into the Excel — get it right before running The "PDF/Reference" links in the generated Excel are absolute file paths built from whatever you type here. They will only work if the ZIP is later extracted to exactly that folder. If you leave the default, extract to your Downloads folder as normal and the links will just work.
5
Run Matching
Automated

Click Run Matching. The progress bar walks through:

1
Statement read
Claude extracts every transaction line, plus the month/year the claim should be filed under
2
Receipts read (in parallel)
Company name, date, amount, document type, and Application Number if it's a MyIPO filing
3
Matched by exact amount
A receipt must equal the transaction amount exactly (floating-point rounding only) — merchant-name similarity only breaks ties between receipts sharing the same amount
4
Categorised
Claude assigns a category and claim status to every transaction
⚡
Receipt parsing is cached per run Re-clicking Run Matching without changing the uploaded statement or receipt files reuses the previous extraction results instead of calling Claude again — no wasted credits.
C — Understanding the Output
6
Reviewing the Results Table
Review

The results table has one row per transaction, color-coded by claim status:

Claimable — MyIPO, Open AI, Claude, Microsoft, Travel Air Ticket, Software Subscriptions, Gov/Regulatory Fees, Utility/Admin
Non-claimable — F&B, Normal Payment, Credit Refund, Bank Interest

Amounts always show 2 decimal places; any negative amount (refunds, credits, payments received) is shown in red.

⚠
If a receipt you expected to match didn't Open the "🔍 Debug: what was extracted from each receipt" expander below the table. It shows exactly what Claude read off every candidate receipt — company, date, amount, currency. Since matching requires an exact amount (no tolerance), even a one-cent misread will prevent a match.
7
Excel Format & Receipt Naming
Reference

The sheet opens with a merged title row above the table:

Title row
Standard Chartered (08 May - 05 June)

Columns (below the title row):

Column order
Posting Date | Transaction Date | No. | PDF/Reference | Description | Currency | Foreign Amount | Amount (RM) | Category | Claim Notes | Supporting Doc Obtained?
  • No. sits next to PDF/Reference so you can match a row to its renamed receipt file at a glance
  • PDF/Reference is a clickable absolute link built from the save location confirmed in Step 4 — see the warning below
  • MyIPO receipts are renamed to their Application Number (e.g. TM2026012345.pdf)
  • All other matched receipts are renamed {No.}. {DDMMYY}_{Receipt|INV}_{Company}_RM{Amount}.{ext} (e.g. 2. 110526_Receipt_AirSelangor_RM166.50.pdf)
8
Downloading & Extracting Correctly
⚠ Read this
  • Click Download Claims Excel only if you just need the report
  • Click Download Excel + Matched Receipts (ZIP) for the full output

The ZIP is named:

Example
Standard Chartered - June Claimable Invoice (2026).zip

Extracting it produces this exact layout (flat, no extra nesting):

📁 Standard Chartered - June Claimable Invoice (2026)/
├── 📁 June_Statement/
├── June Statement (Start - End).pdf
└── 06. June Claimable Invoice (2026).xlsx
└── 📁 Invoice Reference/
└── (renamed, matched receipts)
⛔
Before opening the Excel: extract the ZIP fully first Right-click the downloaded ZIP → Extract All → confirm the destination matches the save location you gave in Step 4 (this is normally the default, since Windows names the extracted folder after the ZIP) → open the Excel from inside that extracted folder.

If you instead double-click the Excel while it's still sitting inside the unextracted ZIP, Windows only pulls that one file out into a temporary folder — the Invoice Reference folder won't be there next to it, and every "PDF/Reference" link will fail with a "Windows cannot find..." error. This is the single most common way these links appear "broken" when nothing is actually wrong with the file.
✅
Nothing in SharePoint (or anywhere else) is touched automatically You always have a chance to review the Excel and the renamed receipts locally before deciding whether — and where — to upload them onward. That upload step is intentionally manual.
D — Troubleshooting
!
Common Problems & Fixes
Reference
ProblemFix
App won't start: "ANTHROPIC_API_KEY not set"Add the key to key.env (Step 1), then restart the app.
"Your account doesn't have enough credit balance"Go to console.anthropic.com → Plans & Billing to add credits, then click Run Matching again.
"Windows cannot find..." when clicking a PDF/Reference linkYou almost certainly opened the Excel from inside an unextracted ZIP, or extracted to a different folder than the one confirmed in Step 4. Extract fully to that exact folder and reopen (see Step 8).
0 transactions extracted from statementStatement may be a low-quality scan. Check it opens and is legible in a normal PDF viewer first.
Receipts uploaded but nothing matchesOpen the Debug expander and compare extracted amounts against the transaction amounts — matching is exact, so even a 1-cent misread breaks it.
Some receipts show an error in the Debug tableUsually an unsupported file type or an unreadable/corrupted file — check the filename and format (PDF, PNG, JPG only).
Re-running gives identical results instantlyExpected — receipt parsing is cached per uploaded file set for this session. Change the statement or receipt files to force a fresh read.
Wrong category assigned to a transactionNo manual override in the UI yet — note it and correct the Excel directly, or flag it for a prompt-rule adjustment.
⛔
This tool never writes anywhere on its own There is no upload/write code path to SharePoint, cloud storage, or anywhere else in this app by design. If a future version needs one, it must be a deliberate, separately reviewed change — not assumed.
